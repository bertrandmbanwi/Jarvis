Isolation

แยกขอบเขต Phase

แต่ละ Phase ระบุ Allowed scope / Forbidden scope ชัดเจน ลดการแก้ไฟล์มั่วและลดบัคข้ามระบบ

Bug Loop

เจอบัค แก้รอบนั้น

หยุดเพิ่มฟีเจอร์ เพิ่ม test จับบัค แก้เฉพาะ scope แล้ว smoke ใหม่ก่อนผ่าน gate

Visible Result

บอสต้องเห็นภาพ

ทุก Phase มีสิ่งที่เปิดดูหรือทดสอบได้จริง เช่น UI label, chat response, popup, voice, dashboard

Bugfix Loop ต่อ Phase

นี่คือวงจรที่ใช้ทุกครั้งเมื่อเจอบัค เพื่อให้การแก้ไม่กระจัดกระจายและไม่ทำให้ Phase อื่นพัง

1. Reproduce

QA ทำให้บัคเกิดซ้ำให้ได้

2. Classify

Lead แยก current / inherited / cross / future

3. Add Test

เพิ่ม test หรือ smoke step จับบัค

4. Fix Scope

Agent แก้เฉพาะขอบเขต Phase

5. Gate Again

run test + real smoke แล้วค่อยไปต่อ

            Testing Matrix ที่บอสเห็นภาพ

            แต่ละ Phase ไม่ได้จบที่ “เขียนเสร็จ” แต่ต้องมี test + smoke + visual result แยกกัน

            กลุ่ม Phaseสิ่งที่บอสเห็นวิธีเทสจริงถ้าเจอบัค
            Phase 0-1 Foundationสถานะ runtime/flags ชัดเจน remote offterminal output, pytest settings/authแก้เฉพาะ process/env/settings
            Phase 2-4 Text Brainหน้าเดิมพิมพ์คุยกับมายได้จริงเปิด UI 3001, ส่ง chat, verify backend=hermesแก้ bridge/route/chat shape เท่านั้น
            Phase 5-7 Memory + Safety + Toolsมายไม่พูด persona เก่า และมี popup ยืนยัน actionถาม memory, trigger fake pending action, verify modalแก้ policy/memory/tool boundary ใน phase
            Phase 8 Voiceคุยเสียงกับมายแบบไม่ซ้ำ ไม่วนไมค์browser push-to-talk, ตรวจ log audio ownerแก้ voice/audio routing เท่านั้น
            Phase 9-10 Full UI + Runbookทุกหน้าเป็น MayAss ใช้จริง/เปิดปิดได้browser smoke ทุก view, npm build, runbook launchแก้ UI surface หรือ launch config ตาม phase
