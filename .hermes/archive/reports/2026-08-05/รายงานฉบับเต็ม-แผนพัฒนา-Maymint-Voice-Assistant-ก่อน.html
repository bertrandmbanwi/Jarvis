0. เป้าหมายจริงของรอบนี้

เป้าหมายหลัก: ทำให้ Maymint มี Voice Assistant ที่ “คุยได้จริง ฟังได้จริง พูดได้จริง หยุดได้จริง และต่อกับสมอง Hermes ได้จริง” ก่อน งานอื่น ๆ เช่น overlay, memory dashboard, mode switch, desktop control ค่อยเสริมหลังฐาน voice แข็งแล้ว

สิ่งที่เราจะยังไม่รีบทำ

  • ยังไม่คุม desktop เต็ม เพราะเสี่ยงและ debug ยาก
  • ยังไม่ทำ wake word ก่อน เพราะถ้าปุ่มพูดยังไม่เสถียร wake word จะพังหนักกว่า
  • ยังไม่ทำ realtime เต็มแบบ ChatGPT Voice ทันที เพราะต้องพิสูจน์ STT/TTS/brain/interrupt ก่อน
  • ยังไม่ rewrite Hermes core เพราะ Hermes คือสมองเดิมที่แข็งอยู่แล้ว

สิ่งที่จะทำก่อน

1. เข้าใจระบบ

รู้ว่าเสียงเข้ามาทางไหน, แปลงเป็นข้อความตรงไหน, เข้า Hermes ยังไง, ตอบกลับเป็นเสียงยังไง

2. ทำเส้นทางเสียงขั้นต่ำ

กดพูด → STT → Hermes → text → TTS → เล่นเสียง

3. เทสเป็นชั้น

เทสไมค์, เทส STT, เทส TTS, เทส brain, เทส interrupt, เทส latency แยกกัน

1. หลักพัฒนาไม่ให้พัง

หลักสำคัญคือ “ไม่เอาของใหม่ไปทับของเดิม” แต่ทำเป็นชั้นหุ้มรอบ Hermes/Maymint เดิม แล้วเชื่อมผ่าน contract ชัดเจน

หลักความหมายผลกับการพัฒนา
เข้าใจฐานก่อนรู้ path ปัจจุบันของ Hermes, memory, provider, STT, TTSลดการติดตั้งซ้ำ/แก้ config มั่ว
ทำทีละชั้นไมค์ → STT → brain → TTS → playback → interruptรู้ทันทีว่าพังตรงไหน
มี test แรกเสมอก่อนเพิ่ม feature ต้องมี smoke testแก้แล้วไม่ทำของเดิมพัง
แยก adapter กับ product logicVapi/Gemini/Local เป็น adapter; Maymint brain/context อยู่กลางเปลี่ยน provider ได้โดยไม่รื้อระบบ
safe defaultเริ่มจาก push-to-talk, short answer, no desktop controlใช้งานได้เร็วและเสี่ยงต่ำ
observableทุก state ต้องเห็น: ฟัง/แปลงเสียง/คิด/พูด/errordebug ง่ายและบอสไม่ต้องเดา

2. ระบบที่มีอยู่ตอนนี้ จากที่ตรวจแล้ว

มายตรวจ context ปัจจุบันแบบไม่ดึง secrets แล้ว พบว่า Maymint/Hermes มีฐาน voice อยู่แล้วบางส่วน

ส่วนสถานะปัจจุบันความหมาย
Hermes brainมี provider/model ใช้งานผ่าน Hermes profileไม่ต้องสร้างสมองใหม่ ให้ voice เรียก Hermes เดิม
STTเปิดอยู่ ใช้ custom command provider openrouter-gemini ผ่าน script openrouter_gemini_stt.py, ภาษาไทยมีเส้นทางแปลงเสียงเป็นข้อความแล้ว ต้องทำ harness เทสให้ชัด
TTSใช้ provider macos-say ผ่าน script maymint_tts.sh, output wavมีเสียงพูดไทย local/free แล้ว เหมาะเป็นฐานรอบแรก
Thai glossaryมี pinned/recent STT termsควรใช้ช่วยแก้คำไทย/technical ที่ฟังผิด
Memoryเปิด memory/user profileVoice ต้องระวังไม่จำทุก transcript มั่ว ต้องมี policy
Jarvis repoมีตัวอย่าง voice listener/speaker/WebSocket/overlayใช้เป็นแหล่งเรียน UX/flow ไม่ควร copy ทั้งก้อน

ข้อสรุป: เราไม่เริ่มจากศูนย์ เรามีสมอง + STT + TTS แล้ว สิ่งที่ขาดคือ voice loop ที่เสถียร, UI state, interrupt/cancel, logging, และ test ladder

3. Voice Stack ที่ต้องเข้าใจแบบลึก

ไมค์→Audio capture→STT→Intent/context→Hermes brain→Text response→TTS→Playback

แต่ละชั้นต้องมีอะไร

ชั้นหน้าที่ต้องวัดอะไรถ้าพังจะเห็นยังไง
Audio captureรับเสียงจาก mic/browser/Discordระดับเสียง, silence, permissionไม่ได้ยิน / อัดเงียบ / permission fail
STTเสียงเป็นข้อความไทยaccuracy, latency, glossary hitคำเพี้ยน / ภาษาไทยหลุด / ช้ามาก
Intent/contextเข้าใจว่าบอสอยากให้ทำอะไรintent preview, risk levelสั่งผิดงาน / ทำเกินคำสั่ง
Hermes brainคิด/ใช้ tools/memory/skillstime to first token, tool visibilityค้าง / verbose เกินเสียง / เรียก tool เสี่ยง
TTSข้อความเป็นเสียงมายduration, quality, speed, truncationพูดเร็ว / อ่าน emoji / ไฟล์เสีย
Playbackเล่นเสียงให้บอสได้ยินdevice, overlap, stop latencyเสียงซ้อน / หยุดไม่ได้ / เล่นผิดที่
State/UIบอกว่ามายกำลังทำอะไรstate transitionsบอสไม่รู้ว่าฟัง/คิด/พูดอยู่ไหม

โหมด Voice ที่ควรมีตั้งแต่ต้น

โหมดใช้เมื่อไหร่ทำก่อน/หลัง
Push-to-talkกดค้าง/กดครั้งเดียวแล้วพูดทำก่อน
Text + voice replyบอสพิมพ์ แต่มายตอบเสียงด้วยทำก่อน
Voice commandบอสพูดสั่งงาน แล้วมายตอบ/ทำทำก่อน
Realtime duplexคุยลื่น แทรกได้ทำหลังฐานเสถียร
Wake wordเรียก “มาย” โดยไม่กดท้ายสุด

4. ฐานที่ต้องทำก่อนลงมือเขียนจริง

Foundation A: Voice Harness

เครื่องมือเล็ก ๆ สำหรับเทสเสียงทีละส่วน เช่น input wav → STT → text, text → TTS → wav, prompt → Hermes → text

Foundation B: State Machine

สถานะกลาง: idle/listening/transcribing/thinking/working/speaking/confirm/error/cancelled

Foundation C: Event Log

บันทึกทุก turn แบบไม่เก็บ secret: timestamps, latency, provider, transcript, final answer, error

Foundation D: Safety Boundary

Voice รอบแรกต้อง default เป็น no-desktop-control, confirmation ก่อน tool เสี่ยง, cancel ได้

10. Definition of Done สำหรับ Voice Assistant v1

  • บอสกดพูด แล้ว Maymint ได้ transcript ไทยที่อ่านรู้เรื่อง
  • Maymint ส่ง transcript เข้า Hermes brain เดิมได้
  • คำตอบเป็นเสียงไทย และมี text transcript คู่กัน
  • กดหยุดเสียงได้ภายในเวลาสั้น
  • ยกเลิก request ที่กำลังคิด/ทำงานได้
  • มี state ชัด: ฟัง/แปลงเสียง/คิด/พูด/error
  • มี latency breakdown
  • งานเสี่ยงไม่ทำโดยไม่ยืนยัน
  • มี log พอ debug แต่ไม่เก็บ secret
  • มี smoke tests ที่รันซ้ำได้
  • ไม่ทำ Hermes CLI/Gateway/Memory เดิมพัง

11. งานถัดไปที่ควรเริ่มจริง

มายแนะนำเริ่มที่ Phase P0–P1 ก่อน: ทำ Voice Harness และ Test Ladder ให้ได้ก่อน อย่าเพิ่งทำ UI สวยหรือ realtime เพราะถ้า STT/TTS/brain/cancel ยังไม่มั่นคง UI จะเป็นแค่หน้าสวยที่ debug ยาก

ชุดงานแรกที่ควรทำ

  1. สร้างโฟลเดอร์ทดลอง voice ที่ไม่แตะ Hermes core
  2. ทำ script voice_doctor ตรวจ STT/TTS/provider แบบ redacted
  3. ทำ script tts_smoke: text ไทย → wav → verify
  4. ทำ script stt_smoke: wav ไทย → transcript
  5. ทำ script full_turn_smoke: audio/text → Hermes → TTS
  6. ทำ log JSON ต่อ turn
  7. หลัง smoke ผ่าน ค่อยทำ push-to-talk UI v0

คำตอบสุดท้ายเชิงกลยุทธ์

ให้คิดว่าเรากำลังสร้าง “ระบบประสาทการได้ยินและการพูด” ให้มายก่อน ไม่ใช่สร้างแอปใหม่ทั้งก้อน พอหู/ปาก/การหยุด/การรู้สถานะนิ่งแล้ว ค่อยเอา overlay, memory dashboard, mode switch, progress UI มาเกาะทีละชั้น ระบบจะไม่พังง่าย เพราะฐานถูกเทสแล้ว

สร้างเป็นรายงาน HTML ภาษาไทยสำหรับวางแผนพัฒนา Maymint Voice Assistant ก่อน โดยใช้แนวทาง foundation-first / phase-by-phase / test ladder
