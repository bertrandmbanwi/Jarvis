6. Backend / API / WebSocket

FastAPI app อยู่ที่ jarvis/core/server.py ขนาดประมาณ 2,781 lines มี route ค่อนข้างเยอะ

HTTP routes สำคัญ

  • /auth/login, /auth/status, /auth/logout, /auth/set-pin
  • POST /chat
  • /jobs, /jobs/{id}, cancel jobs
  • /tools/pending, /tools/confirm
  • /voice/transcribe
  • /health, /perf, /cache, /costs, /models, /privacy, /learning, /agents
  • /api/settings router

WebSockets

  • /ws — main UI chat/audio stream
  • /ws/extension — Chrome extension bridge
  • /ws/overlay — desktop overlay + hotkey activation

Auth มี localhost bypass แต่ remote ต้องใช้ PIN/session token; query-token ปิด default; non-local state-changing request ต้องมี CSRF header X-JARVIS-Client

7. Brain / Agent / Planner / Executor

แกน brain อยู่ที่ jarvis/core/brain.py โดยมี component หลัก:

  • JarvisLLM — cloud/local LLM layer
  • MemoryStore — memory + facts + preferences
  • AgentExecutor — native tool-use loop
  • TaskPlanner — แตก task ซับซ้อนเป็น subtasks
  • AgentCoordinator — route subtasks ไป agent type และ parallel groups
  • QAAgent — ตรวจคำตอบหลังใช้ tools แล้ว retry ได้
  • LearningLoop — record tool reliability / plan outcomes

Flow แบบย่อ: user input → sanitize → local/simple route → select tier fast/brain/deep → enrich memory → ถ้าง่าย executor ทำเลย → ถ้าซับซ้อน planner แตกงาน → coordinator จัดกลุ่ม sequential/parallel → executor เรียก tools → QA retry → save memory/conversation

จุดที่เหมาะกับ Hermes คือ pattern “planner + executor + QA + learning” แต่ไม่จำเป็นต้องย้าย brain จาก Hermes ไปใช้ Jarvis

10. Safety / Permission / Risk Layer

Jarvis มี safety layer ที่ดีระดับหนึ่ง แต่ยังไม่พอสำหรับเครื่องจริงของบอสถ้าจะเปิดเต็ม

สิ่งที่ดี

  • แยก risk level: low / medium / high / critical
  • มี capability tags เช่น shell, local write, browser, destructive, communication, memory
  • มี pending confirmation + timeout fail-safe 120s
  • มี audit DB และ redact sensitive keys
  • Filesystem guard block path ลับ เช่น .ssh, .env, *.pem, keychain, credentials
  • Shell guard block คำสั่งพังเครื่อง เช่น shutdown/reboot/rm -rf

ช่องโหว่/ข้อควร harden

  • high/critical บางตัวไม่ require confirmation เช่น write_file, move_file, chrome_execute_js, chrome_fill_form, run_claude_code, scaffold_project
  • run_claude_code มี env ที่เพิ่ม --dangerously-skip-permissions
  • Playwright persistent profile + cookie sync เสี่ยงโดน session/cookie จริง
  • Memory/facts อาจถูก inject เข้า cloud LLM prompt ถ้า privacy mode off
  • invalid permission mode อาจ fail-open เป็น audit ในบาง path; ควร fail-closed เป็น enforce

11. Voice Stack

Wake word→Record→STT→Brain→TTS→Follow-up
  • Mic: PyAudio / PortAudio, 16kHz mono, chunk 1280
  • Wake word: OpenWakeWord hey_jarvis_v0.1, threshold 0.7
  • STT local priority: Moonshine ONNX → faster-whisper → original whisper
  • Browser mic: MediaRecorder → /voice/transcribe → ffmpeg WAV 16k mono → faster-whisper CPU
  • TTS: Kokoro default → Edge TTS → macOS say
  • มี amplitude envelope ส่งไปขยับ orb ตอนพูด
  • มี follow-up window 8 วินาทีหลังตอบเสร็จ

นี่คือส่วนที่ควรเอา concept มาแทน Maya-ai-1.2 มากที่สุด เพราะออกแบบเป็น pipeline ไม่ใช่ loop ฟังมั่ว ๆ

15. แผนเอามาใช้กับ Maymint/Hermes

ของที่ควรเอา

  1. Swift overlay pattern: floating orb + WebSocket state + global hotkey
  2. Voice pipeline: wake word → STT → brain → TTS → follow-up
  3. Tool registry + permission catalog + contract tests
  4. Pending confirmation + audit + redact summary
  5. Browser bridge pattern แต่ต้อง sandbox/confirm หนัก
  6. Cost dashboard + tier routing
  7. Planner/executor/QA retry pattern

ของที่ไม่ควรเอาทั้งดุ้น

  1. Persona JARVIS/Becs hard-coded
  2. Anthropic/Ollama model wiring แบบตายตัว
  3. Auto kill ports
  4. Cloudflare tunnel แบบไม่ explicit opt-in
  5. Cookie sync / persistent browser profile ที่ไม่ sandbox
  6. Critical tools ที่ไม่ require confirmation

Architecture ที่มายแนะนำ

Maymint Overlay / Voice / Browser UI
        ↓ WebSocket / local gateway
Hermes Brain + configured providers
        ↓ explicit confirmation layer

Oracle vault + Hermes memory + skills
